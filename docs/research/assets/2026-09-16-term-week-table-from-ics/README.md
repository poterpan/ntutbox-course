# 週次表能不能不靠 PDF？—— ics 推導 vs 官方 PDF 週次表

調查日期 2026-09-16。用來決定 `terms/{term}/calendar.json`（交接文件契約三）的
`weeks[]` 要不要繼續依賴解析官方行事曆 PDF。

## 一句話結論

**不需要。** 週次表可以只用 Google Calendar ics 裡兩個具名事件推導出來，
111～115 五個學年度、10 個學期、每期 18 週**逐筆與官方 PDF 週次表相同**。

## 兩條規則

- **第 1 週** = 開學日所在的那一週（週日起算）。PDF 把再前一週標「準備」、不給編號。
- **末週** = 假期開始日（寒假／暑假開始）前一個週六所在的那一週。

週數 18 是**推導出來的**，不是寫死的：兩條規則跑完，10 個學期都得到 18。

## 已知限制

**「開學」關鍵字需要 tie-break。** 措辭逐年不同（115-1「開學暨註冊截止日、開學典禮」，
115-2「開學正式上課、註冊截止日」），規則是**優先取含「正式上課」或「註冊」的那筆**。
111～115 每個學期都剛好收斂到一筆；但 108-1、108-2、109-2 是兩筆命中，
那三個學期沒有 PDF 可對（列表頁當日只掛 112～115），也超出 App 需要的範圍。
將來哪一年收斂不到唯一一筆 → **CI 紅燈，不得靜默猜**。

**彈性學習週是 115 學年度才有的**，舊學期 ics 裡沒有這個事件，`flexible_learning` 必須 optional。

## 檔案

| 檔案 | 內容 |

| `pdf-week-tables-111-115.json` | 從 PDF 抽出的 10 個學期週次表。**這份就是發布端的回歸 fixture**，以後不需要再碰 PDF |
| `extract_pdf_weeks.py` | 上表的萃取腳本（一次性證據萃取，不進發布管線）。`python3 extract_pdf_weeks.py <pdf 目錄>` |

## 對發布端的影響

**丟掉的是執行期依賴**：不再抓 oaa 列表頁（目錄 id `2878` 是 CMS 內部值、會變）、
不解 PDF、CI 不需要裝 poppler。**留下的是證據**：上面那份 10 學期 fixture 變成
ics 解析規則的永久離線回歸基準，取代交接文件契約三原本的不變量 ⑧
（原本只對 115 一個學年度回歸，現在是 10 個學期）。
